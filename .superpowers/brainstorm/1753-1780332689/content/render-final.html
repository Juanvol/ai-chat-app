终极方案：Custom View + 硬件层

TextureView 的代价（额外缓冲/延迟/内存）全部可以避免

为什么 Custom View 就够了？

宠物渲染每帧只做 3 件事：
① 清空画布（透明）
② 画一张精灵图（~150KB Bitmap）
③ 画气泡文字（可选）

这个负载对硬件加速的 Custom View 来说微不足道。
TextureView 是为视频解码/Camera预览设计的——我们不需要它的能力，也就不需要承受它的代价。

推荐方案：Custom View + 硬件层

class PetView(context: Context) : View(context) {

    init {
        // 开启硬件层 — GPU 接管绘制，零额外内存
        setLayerType(LAYER_TYPE_HARDWARE, null)
    }

    private val renderLoop = object : Choreographer.FrameCallback {
        override fun doFrame(frameTimeNanos: Long) {
            physics.update()       // 物理计算
            invalidate()           // 触发硬件层重绘（GPU完成）
            Choreographer.getInstance().postFrameCallback(this)
        }
    }

    override fun onDraw(canvas: Canvas) {
        canvas.drawColor(0, PorterDuff.Mode.CLEAR)  // 透明

        canvas.save()
        canvas.scale(squashX, squashY, cx, cy)      // 弹性挤压
        canvas.drawBitmap(currentFrame, x, y, null) // 精灵帧
        canvas.restore()

        bubble?.draw(canvas)                         // 气泡
    }
}
工作原理
Choreographer.postFrameCallback
→ 与屏幕 VSYNC 同步（比 Handler 准）
→ 每 16.6ms 回调一次

invalidate()
→ 触发硬件层重绘
→ GPU 并行执行 onDraw 中的 Canvas 命令
→ 不阻塞 UI 线程

LAYER_TYPE_HARDWARE
→ View 的绘制结果缓存在 GPU 纹理中
→ 只有 invalidate() 时才重新绘制
→ 内存由 GPU 管理，不计入 App 堆内存
TextureView 为什么是过度设计
TextureView 为 外部图像生产者 设计：
· Camera 预览流 → SurfaceTexture
· 视频解码器 → SurfaceTexture
· OpenGL 渲染 → SurfaceTexture

这些场景需要：
· 独立渲染线程
· 生产者-消费者缓冲队列
· GPU→CPU→GPU 纹理拷贝

我们的场景：
· Kotlin 代码主动画 Bitmap
· 不需要外部生产者
· 不需要独立的 Surface

→ Custom View 足够，TextureView 浪费
