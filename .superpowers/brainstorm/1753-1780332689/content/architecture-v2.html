渲染层修正

SurfaceView 在悬浮窗里透明渲染是已知坑，改用更可靠的方案

❌ SurfaceView — 放弃
已知问题：
· setZOrderOnTop(true) → 盖在所有 View 上面
· PixelFormat.TRANSPARENT → 部分设备无效
· 悬浮窗里 SurfaceView 透明 = 黑屏 or 不显示
· 与 WindowManager 的 z-order 冲突
· Android 各版本表现不一致

结论：不可靠，放弃
✅ TextureView — 采用
为什么可靠：
· 普通 View，不是独立窗口层
· 天然支持透明（Canvas clear → 透明）
· 硬件加速（GPU 渲染）
· 支持 Alpha 动画
· 悬浮窗兼容性无问题

唯一代价：
· 比 SurfaceView 延迟 1-2 帧（~16-32ms）
· 宠物场景完全无感知

TextureView 渲染方案

// TextureView — 普通 View，在 WindowManager 浮窗中正常工作
class PetRenderer(textureView: TextureView) {
    private val frameInterval = 16L  // ~60fps

    fun start() {
        // 使用 Choreographer 同步 VSYNC（比 Handler 更准）
        Choreographer.getInstance().postFrameCallback(renderLoop)
    }

    private val renderLoop = object : Choreographer.FrameCallback {
        override fun doFrame(frameTimeNanos: Long) {
            val canvas = textureView.lockCanvas()
            if (canvas != null) {
                canvas.drawColor(0, PorterDuff.Mode.CLEAR)  // ← 透明！
                petSprite.draw(canvas)   // 绘制精灵帧
                bubble.draw(canvas)      // 绘制气泡
                physics.update()         // 更新物理
                textureView.unlockCanvasAndPost(canvas)
            }
            Choreographer.getInstance().postFrameCallback(this) // 下一帧
        }
    }
}
