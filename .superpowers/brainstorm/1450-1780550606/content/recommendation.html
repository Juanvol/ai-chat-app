我的推荐排序：B → D → C（A 单独赛道）

核心逻辑：先让宠物「有用」，再让它「有感情」，最后让它「有个性」

为什么这个顺序？

🥇 第一优先：B — Agent 集成

把宠物从「贴图」变成「有用的 AI 伙伴」

当前问题

  • 宠物只会随机漫步，没有「灵魂」
  • 用户发消息给 AI → 切到聊天页看回复
  • 宠物和 AI 是两件无关的事

改完后

  • 发消息 → 宠物自动切 run 动画（AI 工作中）
  • 流式返回中 → talking 动画
  • 完成 → wave + 气泡「我帮你整理好了~」
  • 出错 → failed 动画 + 「信号不好喵...」
  • 点宠物 → 弹出迷你聊天，不切页面

✓ 为什么先做

  • 最大差异化 — 市面上没有 AI 状态指示器宠物
  • 低阻力 — 动画状态 spritesheet 里都有 (run/failed/review/jump/talking)
  • 复用现有 — LLMClient 流式管道只需加状态回调
  • 立刻可感知 — 用户发一条消息就能看到变化

⚠ 注意

  • 需在 DeepSeekClient 流式回调中插入状态通知
  • 迷你聊天需要原生层 Dialog/浮窗（不依赖 Flutter 页面）

🥈 第二优先：D — 养成深化

让用户「在乎」宠物，产生每日打开的情感驱动力

当前问题

  • PetController 状态机写了但原生层不响应
  • 喂食按钮点了 → Flutter 数据变了 → 宠物动画不变
  • hunger/mood 衰减了 → 宠物不知道

改完后

  • hunger < 30 → 自动切 hungry 动画 + 气泡「好饿喵...」
  • energy < 20 → sleepy → 趴下睡觉
  • 喂食 → eating 动画 + 开心表情 + affection +10
  • 好感累积 → 解锁新对话/新动画/阶段称号
  • 每天打开 → 「糯糯想你了~」温暖互动

✓ 为什么第二

  • 情感粘性 — 养成是长期留存的核心
  • UI 已就绪 — PetCenterScreen 的按钮/状态条都在
  • 数据模型已有 — PetState + PetController 只需要接线

⚠ 注意

  • Flutter→原生 MethodChannel 通信量增大
  • 状态机逻辑要严谨（防抖/边界/恢复）
  • 日记需要 AI 截图管线，可后置

🥉 第三优先：C — 生态开放

多皮肤 + pet.json 导入 + 可提交到 Petdex

当前问题

  • 只有一只 Nyami 猫娘（用户还说不好看）
  • 换宠物要替换 assets 文件重编译
  • 格式已对齐 Petdex 但没利用起来

改完后

  • 设置页 → 「换皮肤」→ 从 Petdex 浏览/下载
  • 支持 pet.json → 自动解析 spritesheet
  • 用户自创 → 弗糯糯新形象可提交到 Petdex
  • 内置 3-5 只预设角色

✓ 为什么第三

  • 内容无限 — 接入 Petdex = 接入整个社区
  • 格式已对齐 — loadSpritesheet() 已经是 Petdex 标准
  • 低耦合 — 独立模块，不影响已有功能

⚠ 注意

  • 皮肤管理 UI 需从零搭建
  • 下载/缓存/验证需要网络 + 存储逻辑
  • 不同 spritesheet 尺寸可能不同（需兼容）

🔮 A — AIRI 交互深度：单独赛道，不排入主序列

Live2D/VRM + 语音 — 需要架构级变更，不是功能叠加

为什么暂不排入

  • Live2D/VRM 需要 WebGL → Electron/Tauri
  • 当前是 Android 原生 Kotlin 渲染管线
  • 架构切换成本 > B+C+D 加起来的总和
  • 移动端 Live2D 性能未经验证

什么时候值得做

  • B+C+D 全部完成，产品稳定
  • 用户反馈「想要更生动的角色」
  • 考虑 Windows/macOS 桌面版时
  • 可以从 语音对话 作为轻量切入点（不需 Live2D）

总结

推荐路线图
Phase 1 🤖 Agent 集成 LLM 状态→动画映射 + 迷你聊天 ~2 周
Phase 2 🎀 养成深化 状态机接线 + 喂食/玩耍响应 + AI 日记 ~2 周
Phase 3 📦 生态开放 pet.json 皮肤系统 + Petdex 集成 ~1 周
Phase 4+ 🔮 交互深度 语音对话 → 桌面版 → Live2D 待评估

核心思路：Phase 1 让宠物从「背景装饰」变成「AI 前台」，Phase 2 让用户产生情感依赖，Phase 3 打开内容供给。三步走完，弗糯糯就是一个有灵魂、有记忆、有个性的 AI 伴侣。

你觉得这个排序逻辑如何？同意的话说 "OK" 我继续推进设计细节；想调整的话说你的想法。
