AI 集成 + 日记：能用吗？

逐项盘点已有代码 vs 缺失部分

🤖 Agent 集成 — 80% 已就绪

已有能力（已验证存在）
PetAgentCore.chatStream()流式聊天，含 onChunk/onDone/onError 回调
PetAgentCore._evaluate()LLM 决策管道，输出 action JSON (bubble/move/flip/speak/silent)
PetAgentCore._perceive()定时感知循环，读取 hunger/energy 真实状态
PetBrain (BehaviorWeights)时段/状态/关注度加权随机行为选择
PetAiService.generateSuggestion()上下文感知 + LLM 主动建议，含计时器
PetAiService.analyzeScreenshot()MiMo Vision 截图分析 → DeepSeek 建议，含记忆保存
PetController.feed/play/pet/sleep()用户交互触发器，含状态转换 + 过渡计时
原生 playAnim/showBubble原生层已接受动画/气泡命令
Spritesheet 状态idle/run/failed/review/jump/talking/wave/sleeping 全部有帧
缺失部分 — 只有 3 根线要接

❌ 线 1：LLM 流 → 原生动画

chatStream 开始 → // 没调 playAnim("run")
onChunk 首段到达 → // 没调 playAnim("talking")
onDone → // 没调 playAnim("wave")

修复：在 chatStream 回调中加 3 行 MethodChannel 调用。

❌ 线 2：状态机 → 原生

PetController.feed() → state.status = eating → // 原生宠物不知情
_decay() → hunger < 30 → status = hungry → // 原生宠物不知情

修复：PetController.onStateChanged 回调 → MethodChannel → playAnim("hungry")。

❌ 线 3：点宠物 → 迷你聊天

用户点宠物 → onTouchEvent("tap") → // 原生层没有弹出聊天UI

修复：原生层收到 "tap" → 显示一个 Dialog/浮窗输入框 → MethodChannel 发文本 → PetAgentCore.chatStream → 回传气泡。

📖 日记 — 60% 已就绪

已有能力
PetDiaryScreen完整 CRUD UI — 写日记/查看/删除/清空，自动/手动标签
PetAiService.saveMemory()自动保存到 pet_memories + memories 双 Box
PetController state tracking每次交互都有时间戳 + 状态变更记录
Interaction time windowlastInteractionAt + isDeepSleeping 等上下文信息
缺失部分

❌ 缺 1：自动日记生成

用户喂食 → PetController.feed() → // 没有自动写日记
用户聊天 → chatStream done → // 没有自动写日记

修复：在关键交互节点调用 PetDiaryService.addEntry(type:'auto', ...)，用 LLM 一句话总结交互。

❌ 缺 2：日记 LLM 润色

日记内容目前是模板文字，不是 AI 生成的自然语言

修复：复用 PetAiService 的 LLM 管道，每日总结时让糯糯"写日记"。

结论

都能用，而且不需要从零造。核心能力（流式聊天、状态机、视觉分析、记忆、原生渲染、精灵图）全部就绪。Phase 1 的工作量主要是「接线」——在已有模块之间建立回调通道，而不是写新模块。
